Documents and files

A document holds your stage settings, timelines, library and media. This page covers creating one, the file formats Phoenix reads and writes, bringing in images, sound and video, and getting work back after a crash.

Create a document

Choose File › New... (Ctrl+N). Pick a category on the left, then a preset. The details on the right fill in from the preset, and you can change any of them.

Width and height can be from 1 to 8192 pixels. The frame rate list runs from 8 to 120 fps and includes the broadcast rates 23.976, 29.97 and 59.94; you can also type any rate. Phoenix remembers your last choice and opens on it next time.

Document settings

To change the settings of an open document, click an empty part of the stage with the Selection tool so the Properties panel shows the Doc tab.

W and H
The stage size in pixels.
FPS
Frames per second, from 0.01 to 120.
Stage
The background color of the stage, which also becomes the background of exported video.
Scale spans
When this is on, changing the frame rate stretches or squeezes every span so animation keeps its timing in seconds. When it is off, each frame keeps its place and the animation plays faster or slower.

The tab also shows which application and file version last saved the document.

The window title shows the document's full path, with a * after it when there are unsaved changes. Before closing a changed document, Phoenix asks whether to Save, Discard the changes, or Cancel.

Saves are safe: Phoenix writes to a temporary file and only replaces the original once the new file is complete, so a crash or full disk in the middle of a save cannot damage your file.

Working with FLA files

Phoenix is built to round-trip Animate files. When you open an FLA and save it again, Phoenix keeps everything it found, including settings and data it does not use itself, such as publish settings, scripts and shape hints. The saved file opens in Animate as before.

Some things Phoenix can do have no place in an FLA. If saving as FLA or XFL would leave something out, Phoenix tells you what before it writes, so nothing is lost silently.

Older Flash files

Files from Flash CS4 and earlier use a binary format that Phoenix converts on open. When you save one, Phoenix asks whether to save under a new name or replace the original. A few of these files, such as those with a bitmap placed on the stage or a video, cannot be converted yet; Phoenix says so instead of opening part of the file.

The Phoenix format

Phoenix documents (.phx) are Phoenix's own format. They hold everything an FLA can, so you can always export a .phx back to the same FLA, and they leave room for features FLA cannot store.

  • Fast. A .phx typically opens several times faster than the same FLA.
  • Media kept as is. Images, sounds, video and fonts are stored in their original formats, each stored once even if used many times, and loaded only when needed.
  • Robust. Each part of the file is checksummed, so damage to one part does not take the whole file with it.
  • Compatible. An older Phoenix opens files from a newer one and keeps any data it does not understand. If a newer feature would change how something looks, the older version opens the file read-only and tells you what is missing.
  • Previewable. Each file carries a thumbnail of its first frame.

To convert files without opening them, see the --convert option.

If you import one image from a numbered sequence, such as walk_0001.png, Phoenix offers to import the whole sequence as consecutive keyframes.

You can also drag images and sounds from your desktop. Dropped on the stage, they are placed where you drop them; dropped elsewhere, they go into the library. An image copied in another app can be pasted straight onto the stage.

Auto-save and recovery

While a document has unsaved changes, Phoenix writes a recovery copy in the background. It never touches your own file. Choose how often under File › Auto-Save: every minute, every 2 (the default), 5 or 10 minutes, or off.

If Phoenix closes without saving, for example after a crash or power cut, it offers the recovery copy the next time it starts:

Recover
Opens the recovered work. Save it to keep it.
Discard
Deletes the recovery copy.
Later
Keeps the copy and asks again next time.
