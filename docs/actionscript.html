ActionScript and Test Movie

ActionScript is the scripting language of Flash movies and games: buttons that answer clicks, clips that follow the keys, scores kept in text fields. Phoenix writes it in the Actions panel and plays it in Test Movie, ActionScript 1 and 2 as older movies have it and ActionScript 3 frame scripts with their event listeners. HTML5 Canvas documents' JavaScript plays there too.

Where scripts go

A script belongs to one of two places:

A keyframe
It runs each time the playhead reaches that frame: on the main timeline, or inside a movie clip as the clip plays. Most scripts go here, and in ActionScript 3 all of them do. A layer named actions at the top of the timeline, with nothing else on it, keeps them easy to find.
A button or movie clip instance
ActionScript 1 and 2 only. A button's script holds handlers such as on (release) { ... }, run when it is clicked; a movie clip's holds onClipEvent (enterFrame) { ... } and the like.

Scripts reach movie clips, buttons and text fields by their instance names, set in the Properties panel: a clip named hat is hat to the script on its timeline. Library symbols are reached by their linkage, set in the library's symbol properties (exported for ActionScript, with an identifier or a class name).

The Actions panel

Window › Actions (F9) shows the script of the keyframe at the playhead on the current layer, ready to type into. Select a button or movie clip instance on the stage instead and it shows that instance's own script.

  • What you type goes into the document as you type. Each script you work on is one step in the undo history until you move to another script or click away, so Ctrl+Z on the stage takes back the whole edit. Inside the editor, Ctrl+Z undoes typing.
  • The script navigator on the left lists every script in the document, scene by scene and symbol by symbol. Click one to edit it without moving the playhead. The ☰ button shows or hides it.
  • Pin keeps the script in the panel while you select other things and move the playhead. Picking a script in the navigator pins it; click Pin again to follow the selection.
  • Check checks the script's syntax. It is also checked each time it goes into the document: the line with an error is marked, and the line below the editor says what is wrong.

Writing code

  • Code hints. Type a dot and what can follow it is offered: a clip's methods and properties, MouseEvent.'s events, Key.'s keys. Ctrl+Space offers every word that fits what you have begun, the instance names on the timeline among them. Arrow to one and press Enter or Tab; Esc closes them.
  • Snippets puts in ready-made code for what movies often do: stop at a frame, go to a frame on a click, show or hide, drag and drop, move with the arrow keys, count clicks in a text field, play a library sound. Those for ActionScript 2 go in a button's or clip's script; those for ActionScript 3, and the JavaScript ones for HTML5 Canvas documents, in a frame's. A snippet that works on an instance asks which.
  • Target (Insert Target Path) lists the named movie clips and buttons the script can reach, those inside them too, and types the path to the one you pick at the caret: this.hat.bow, or from the root (_root.hat.bow, or exportRoot.hat.bow in an HTML5 Canvas document) for a script on a scene's timeline. Only instances with a name are listed.
  • Find (Ctrl+F) finds, and Ctrl+H replaces. Ctrl+G goes to a line, and Ctrl+/ comments the selected lines out or back in.
  • Tab and Shift+Tab indent and outdent the selected lines. A new line keeps the indent, one step deeper after an opening brace, and a closing brace steps back.

ActionScript files (.as) open in Commands › Script Editor, the same editor in a window of its own; see Write a script.

Test Movie

Control › Test Movie (Ctrl+Enter) plays the movie in a window of its own as Flash Player would, at the document's frame rate, running its ActionScript. It starts at the first scene and plays the scenes in turn, back to the first after the last. Buttons light up under the mouse and answer clicks, and keys typed in the window go to the movie, so an interactive movie, such as a dress-up game, can be played.

  • The first button, Restart, plays it again from the first frame.
  • Pause holds it where it is (it then shows Play); Step moves the paused movie on one frame at a time.
  • The time slider shows where the scene is; click or drag it to go to another frame, whose scripts run as a gotoAndPlay would run them. Beside it are the scene and frame, and whether the timeline has stopped.
  • Esc, or closing the window, goes back to editing. Playing never changes the document.

Buttons and movie clips are clicked by their art, so a click between two buttons finds neither. Click an input text field to type into it.

ActionScript 1 and 2

As older movies and games are written, they run as Flash Player runs them:

  • Frame scripts run as their keyframes are reached, on the main timeline and in every movie clip, after the frame's objects are placed.
  • stop(), play(), gotoAndPlay(), gotoAndStop(), nextFrame() and prevFrame(), on the timeline or on a named clip (hat.gotoAndStop(3)), and tellTarget.
  • nextScene() and prevScene(), and gotos that name a scene (gotoAndPlay("Ending", 1)) or a label in another scene.
  • on (release), on (press), on (rollOver) and the other button events, on (keyPress "<Left>"), and onClipEvent (load), (enterFrame), (keyDown), (keyUp), (mouseDown), (mouseUp) and (mouseMove) on movie clips.
  • A clip's _x, _y, _visible, _alpha, _xscale, _yscale, _rotation, _width, _height, _currentframe, _totalframes, _xmouse and _ymouse, read and set by dot (hat._visible = false) or with getProperty and setProperty, and clips found by name or by path ("/hat", _root.hat, _parent).
  • The keyboard: Key.isDown(Key.LEFT), Key.getCode(), Key.getAscii() and Key.addListener().
  • Selection.setFocus("name_txt") and getFocus(), for input fields.
  • Variables, if, loops, functions (constructor functions with new too), arrays and objects, ifFrameLoaded (everything counts as loaded) and trace(), whose output goes to the Output panel (F2).

ActionScript 3

An ActionScript 3 movie (as its publish settings say) plays with the flash.* classes, over the display list: everything on the stage is a display object scripts can find, move, filter, draw into and take apart, and every class can be made with new, extended, and tested with is and instanceof.

  • The display list. Sprite, Shape, MovieClip (its frames, labels and scenes: currentFrame, currentLabel, currentLabels, scenes, gotoAndStop with a scene, addFrameScript), SimpleButton, Bitmap, TextField, and the Stage (stageWidth, frameRate, focus, invalidate() and the rest). Children are added, removed, reordered and found by name; objects have their position, scale, rotation, alpha, filters, blend mode, mask, scroll rect, transform, bounds, and hit tests. What the timeline places is the same objects: a frame's named instances are its timeline's variables, and a class that declares them gets them.
  • Drawing. graphics: lines, fills (solid, gradient and bitmap), rectangles, circles, ellipses, curves, drawPath and drawTriangles. BitmapData with all its methods, from getPixel32 and fillRect to draw, copyPixels, threshold, applyFilter, floodFill and perlinNoise.
  • Events. EventDispatcher with capture, target and bubble phases, priorities, stopPropagation and preventDefault; Event, MouseEvent, KeyboardEvent, FocusEvent, TextEvent, TimerEvent, ProgressEvent, IOErrorEvent and the rest. Classes of your own may extend EventDispatcher or Event; an event sent again goes as its clone(). The pointer and the keys reach what is under them and the focus, and the stage hears every key.
  • Geometry and filters. Point, Rectangle, Matrix, ColorTransform and Transform; BlurFilter, DropShadowFilter, GlowFilter, BevelFilter, the gradient filters, ColorMatrixFilter and ConvolutionFilter (a display object's filters are copies, as the player keeps them); fl.motion.AdjustColor.
  • Data, time and the web. ByteArray (every read and write, both byte orders, compress and uncompress), Timer, setTimeout, setInterval and getTimer, which keep the movie's time. URLLoader loads text, bytes and variables, and Loader loads PNG, JPEG and GIF images, from files beside the movie or from the web; navigateToURL opens web pages in your browser. Anything the movie sends to the web is shown in the Output panel; navigateToURL sends no form data, and says so. SharedObject.getLocal keeps what a movie saves with Phoenix's settings.
  • Library symbols are classes. A symbol exported for ActionScript is its class: new CloseButton() makes one, getDefinitionByName("CloseButton") finds it, and each instance a timeline places is one, its constructor run as it is placed and before the frame's scripts. A symbol without a class file gets the class the player would make for it. Bitmaps and sounds exported for ActionScript are BitmapData and Sound classes.
  • Frame scripts belong to their timeline: what frame 1 declares, later frames see, this is the timeline, and the flash.* classes need no import. With a document class, they run in its instance.
  • Components. The fl.controls components (Button, CheckBox, ComboBox, List, Slider and the rest) are Phoenix's own, written in ActionScript: placed on the stage, they take the parameters set in the Component Parameters.

Class files

An ActionScript 3 movie can keep its code in class files (.as). Test Movie loads each class the first time a script needs it, by its name: game.Hat is game/Hat.as, looked for in turn in the document's folder, the source paths in its publish settings, the sources kept beside a library the publish settings list (the src folder beside a .swc's lib folder), any src folder in the document's folder or the folders in it, the class paths in Edit › Preferences › ActionScript, and last Phoenix's own classes.

  • The document class, named in the publish settings, is the main timeline's: its constructor runs before the first frame's scripts, with the first frame's instances placed, and frame scripts see its methods and fields.
  • A symbol's class, its linkage class name, is what each clip of the symbol is.

A class that does not compile shows its file and line in the Output panel, as a frame script does. File › Publish compiles the same classes into the SWF movie (see SWF movies).

Published movies

An SWF movie opened in Phoenix keeps the ActionScript 3 compiled into it, and Test Movie runs it: the main timeline is an instance of the movie's own main timeline class, each symbol linked to a class is that class, and the frame scripts are the ones that class gives its frames. The classes compiled into the movie come first, so a movie built with the components runs its own copies of them rather than Phoenix's. A movie that loads shared libraries before it starts (a preloader for text layout framework text) plays the movie it would load.

  • The compiled code runs as published, with no source to show: an error names the class and method it stopped in, with the place in the method's code.
  • Text layout framework text, which comes from a shared library rather than the movie, shows as plain text in its box, in the font, size and color of its first run.
  • Saved as a document, the movie keeps its compiled code (in bin/abc) and still runs it in Test Movie; the code itself cannot be edited.

HTML5 Canvas JavaScript

An HTML5 Canvas document's scripts are JavaScript, written for CreateJS, the library its published web page plays with. Make one with File › New, choosing HTML5 Canvas as the Platform; a Canvas document made elsewhere opens as one, and keeps its publish settings when saved. The Actions panel edits and checks its scripts as JavaScript, with JavaScript snippets, the Document Info in the Properties panel shows its Platform, and Test Movie runs it:

  • Frame scripts run as their keyframes are reached, on the main timeline and in every movie clip, each as a function of its own: this is the timeline, and what a script declares with var is its own, so keep what later frames need on the timeline (this.score = 0).
  • Timelines. stop(), play(), gotoAndPlay() and gotoAndStop() by frame number or label. Frames count from 0 in JavaScript: this.gotoAndStop(0) goes to the first frame. currentFrame (from 0 too), totalFrames, currentLabel, labels, paused, and loop = false to stop on the last frame.
  • Instances by name: this.ball, with x, y, rotation, scaleX, scaleY, alpha, visible, name, parent, children, mouseEnabled and cursor = "pointer" (a hand over it); localToGlobal, globalToLocal, getBounds and hitTest. Text fields: this.score_txt.text = "Score: " + score. exportRoot is the main timeline and stage the stage, with mouseX, mouseY and canvas.width.
  • Events. addEventListener, removeEventListener, on() (with its scope, once and data) and off(), and dispatchEvent for events of your own. Clips hear click, dblclick, mousedown, mouseup, mouseover, mouseout, rollover, rollout, pressmove, pressup and tick; the stage stagemousedown, stagemouseup and stagemousemove; window and document hear keydown and keyup. Mouse events go up from the clip under the pointer to the main timeline, and stopPropagation() stops them. function () { ... }.bind(this) works as in a browser.
  • Time. createjs.Ticker (framerate, getTicks(), getTime() and its tick event); createjs.Tween.get(this.ball).to({x: 300}, 1000, createjs.Ease.quadOut), with wait, call, set and loop, and the createjs.Ease curves; setTimeout and setInterval. All of them keep the movie's time.
  • The library. new lib.Ball() makes a clip of a library symbol, by its linkage or its name, and addChild puts it on a timeline. createjs.Sound.play("linkage") plays a library sound.
  • console.log() and alert() write to the Output panel, as trace() does.

What Test Movie does not have yet, such as drawing from scripts (createjs.Shape and Graphics), new Text and Bitmap objects, filters and caching, says so in the Output panel when a script asks for it: that script stops there, and the movie plays on. A script that runs for more than five seconds (a loop that never ends) is stopped the same way.

What games use

In both versions:

  • Text fields. A dynamic or input text field with an instance name is reached by it, and score_txt.text = "Score: " + score changes what it shows, in its own font and color. A field that names a variable (ActionScript 1 and 2) shows the variable's value as it changes, and typing into such an input field sets the variable.
  • Typing. Click an input field, or focus it from a script, and type: the text goes in at the end, Backspace takes off the last character, and Enter starts a new line in a multiline field.
  • Dragging. startDrag() and stopDrag(), with a lock to the center and bounds, as a function or on a clip; _droptarget (or dropTarget) says where it was let go.
  • Hit tests. hitTest(x, y, shapeFlag) and hitTest(otherClip), and hitTestPoint and hitTestObject; with the shape flag, the clip's art counts rather than its box.
  • Clips from the library. attachMovie("linkage", "name", depth, {_x: 10}), duplicateMovieClip() and removeMovieClip(), for symbols exported for ActionScript.
  • Sound. Sounds placed on keyframes play as the frames are reached, as their sync and loop settings say. Library sounds exported for ActionScript play from scripts: new Sound() with attachSound("linkage"), start(seconds, loops), stop() and setVolume(), or a sound's class with play(); stopAllSounds() and SoundMixer.stopAll() silence them.
  • getTimer() counts the milliseconds since the movie started, and getURL() opens web links in your browser.

Errors and trace

What scripts trace() goes to the Output panel (F2). A script error stops that script only, and is shown in the Output panel, in red, with the frame or button and the line it was on, and in ActionScript 3 the functions it was in; the movie plays on, and the line below the movie counts the errors.

Once the Test Movie window is closed, double-click an error in the Output panel to see its script in the Actions panel with the caret on that line.

To check a movie's scripts without a window, for a whole folder of games say, use Phoenix play on the command line: it plays the movie, prints what its scripts trace and the errors they stop on, and can click every button in turn.

Simple frame actions while animating

Playback on the stage, and exported movies, do not run scripts. With Control › Enable Simple Frame Actions on, they follow the simple calls in frame scripts (stop(), play() and the gotos), which is enough for a pose held or a section repeated; see Frame scripts.
