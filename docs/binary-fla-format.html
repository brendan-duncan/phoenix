The binary FLA format

Before CS5, Flash saved .fla files in a binary format: a Microsoft compound file (OLE2) whose streams hold MFC-serialized objects. Phoenix reads them by converting them to XFL in memory (src/parser/compound_file.cpp, src/parser/binary_fla.cpp) and parsing the result as any other document.

The format is undocumented. This description builds on the independent reverse engineering in fla-decoder (MIT, Ed Moore), corrected and extended by checking a Python prototype field by field against the corpus documents that exist in both formats (Yard_Sale_03 / Yard_Sale_03_2, Freya_Fairy_07 / Freya_Fairy_07_2). All 183 streams of the three binary corpus files parse to their last byte. Flash 8 (Contents 0x138), which has no twin in the corpus, was worked out structurally from 20 production files (about 10,000 streams), every stream of which now parses to its last byte; what is new in it is marked [S].

Confidence tags used below:

  • [X] confirmed against an XFL twin. The counts are items compared, all matching unless a mismatch is stated.
  • [S] structurally confirmed: the field size is right because every stream parses to its exact end, but its meaning is unknown or guessed.
  • [G] guessed, with no evidence in the corpus.

0. Versions seen

When Flash saves, it copies unchanged Symbol streams verbatim. A single file can therefore mix object schemas (Freya Symbol 14 is MX 2004 era), so a decoder must branch on the schema of each object, never on the file version.

Contents versions: the low byte is the version, and the high byte is 0 or 1 with nothing else changed [S] (both are found for most versions; 0x43 is a CS4 save in CS3's layout). Among 1,600 binary FLAs from 1999 to 2010 [S]:

Version Saved by Bytes before the scene list
0x1B Flash 5 5
0x20 MX 9
0x29 MX 2004 13
0x38 Flash 8 17
0x3F Flash 8 (later saves) 21
0x43 CS3 25
0x47 CS4 ("Saved by Adobe Flash Windows 10.0") 29

CS3 and CS4 can name their streams P N <time>, S N <time> and M N <time>. Only a few Contents records follow the file version rather than a schema of their own (the ItemHeader tail, the profiles list, the sound record's last u32, the swatch list ends); everything in the timeline streams branches on schemas.

Their timeline streams use only the classes below, plus CCommandObj (Flash 5, not read).

1. Container and primitives

  • OLE2 compound file. Streams: Contents, Page N (scenes), Symbol N (library symbols), Media N (bitmaps and sounds).
  • Little endian throughout.
  • CString (MFC): u8 n. If n is 0xFF: u16 n; if that u16 is 0xFFFE the string is UTF-16, so read the length again (u8, or FF+u16, or FFFF+u32) and then n UTF-16 code units. Otherwise the string is n ANSI bytes. Empty strings are 00 (ANSI) or FF FE FF 00 (Unicode).
  • wstr8: u8 n + n UTF-16 units with no marker. Used for stream names in Contents when the record schema is at least 22 (CDocumentPage; 22 is Flash 8 [S]) or at least 6 (CMedia*). Older records use an ANSI string (u8 n + bytes).
  • color: 4 bytes R, G, B, A. [X]
  • matrix: 6 x s32: a, b, c, d as 16.16 fixed point, then tx, ty in twips (divide by 20 for px). [X] 260 instance matrices plus all shape matrices.
  • itemID: u32 time, u32 counter, the XFL itemID="tttttttt-cccccccc". (0, 0) means none. [X] every symbol, media item and folder.
  • CArchive object (MFC ReadObject):
    • u16 tag.
    • 0x0000 means null.
    • 0xFFFF declares a new class: u16 schema, u16 len, ASCII name. It appends the class and then the object to the load table.
    • 0x8000|i is a new object of the class at load index i (appends one entry).
    • Any other value below 0x8000 is a back-reference to an object that was already loaded.
    • 0x7FFF is followed by a u32: once the load table passes 0x7FFE entries, class and object indices no longer fit in 15 bits. Bit 31 set means a new object of the class at index u32 & 0x7FFFFFFF, clear a back-reference to that object. [S] Terrence Page 1, 2 MB.
    • An object can only refer back to one whose reading has finished; a reference to one still being read (itself or an ancestor) is damage.
    • The load table starts at index 1. The class-level schema was 1 everywhere (0 for CColorDef), so the real versioning is a schema byte inside each object.
    • Back-references matter. A folder layer is first serialized inline inside its child layer's parent field. When it shows up later in the page's layer list, that entry is only a back-reference. [X]

2.8 Groups

A CPicShape child with objFlags bit0 = 0 is an XFL DOMGroup [X 78]. Its own shape is the first member; the CPic children follow. All member matrices are in the parent coordinate space; the group matrix equals the matrix of its own shape.

2.9 Action block (frames, sprites, buttons)

u32 version (0 = MX, 1 = MX2004, 4 = Flash 8, 5 = CS3 and CS4), u32 kind
version 0: nothing more, but as below for kind 0 and 1 [S]
otherwise: u32 id/hash, u32 n (0 but once, a CS4 button with 1)

Action list (MX and MX 2004 scripts written in normal mode) [S]: u32 0, u32 n, then n actions, each a u32 naming it and its fields (u = u32, s = CString): 0x00 go to (uussu), 0x01 next frame, 0x02 stop, 0x04 play, 0x05 get URL (ussu), 0x08 tell target (usu), 0x0A if frame is loaded (ussu), 0x0B on a button event (uuu), 0x0C end of the event, 0x0F if (us), 0x10 end of the if, 0x11 else if (us), 0x12 else, 0x13 end of if frame is loaded, 0x17 set property (uususu), 0x18 set variable (ususu), 0x1A with (usuuuuu), 0x1C comment (us), 0x29 expression (us), 0x2C for (usss), 0x3E call (usss); 0x09, 0x1D, 0x2D and 0x2E end blocks. Blocks nest by their end actions. Read from 700 lists; an action not in the table stops the stream. Flash 5 actions (frame schema 18, button schema 4) are records rather than script text [S]: u32 n, then n x (u8 9, u32 action, 5 bytes, 3 x CString, 32 bytes, u32 -1, u16, 2 x CString, 67 bytes). The strings are the parameters ("allowscale", "false" for an fscommand; "MouseDown = true" for an expression). Phoenix reads past them.

4. Media streams

A Media N stream has the same bytes as the XFL bin/Media N.dat file of the same number: 11 of 16 Yard media are byte-identical, and the others are the same format recompressed. Phoenix's existing .dat handling therefore applies directly (Bitmap::datData).

  • Lossless bitmap layout: 03 05, u16 rowBytes, u16 w, u16 h, 4 x s32 frame (twips: 0, frameRight, 0, frameBottom) [X], u8 flags (bit0 alpha), u8 1, then chunks of u16 len + bytes until len = 0. Together the chunks form one zlib stream of ARGB, premultiplied. [X]
  • JPEG bitmaps start with FF D8.
  • MP3 sounds are raw frames. Other sounds are raw PCM in the CMediaSound format.

5. Mapping to XFL (summary)

  • DOMDocument: width, height, frameRate, backgroundColor come from Contents §3.
  • Library item: CDocumentPage, plus the timeline in Symbol N.
  • DOMSymbolInstance libraryItemName: the instance u32 symbol, looked up as the Symbol N library path.
  • Layers: reverse the stored order. parentLayerIndex comes from the parent object.
  • Frame index is the sum of the earlier durations.
  • Elements: in the order stored, with the frame's own shape first. CPicShape maps to DOMShape (flags bit0) or DOMGroup. CPicSprite, CPicSymbol and CPicButton map to DOMSymbolInstance with symbolType movie clip, graphic and button. CPicText maps to DOMStaticText.
  • Shapes: edges convert to XFL edge strings one-for-one (same 1/256-twip units, the same fill0/fill1/stroke indices).

6. Not covered by the corpus (still unverified)

  • Which custom ease curves the frame uses (one for all, or one per property): seen only on untweened frames.
  • Frame labels and ease: the Flash 8 files have labels ("wave", "Short bounce") and eases of -100 and 100 where 2.4 puts them, but no XFL twin to compare against [S].
  • Shape tweens: the CPicMorphShape layout is structural only (2.11), and one with a gradient or bitmap fill has not been seen.
  • Mask/guided layer type codes.
  • Tint and advanced color modes.
  • Dynamic/input text.
  • Text filters.
  • Bitmap instances (CPicBitmap): structural, and the matrix taken as pixels to the parent from one file [S].
  • Video: the library items and stage instances are structural [S], and the video data in their streams is not read.
  • CPicButton instance names.
  • Flash 5 actions as scripts: the records are read past (2.9), not turned into ActionScript.
  • Some objects in the older files: of the 1,616 binary FLAs surveyed, all open and 1,397 read with nothing missing; in the rest, about 560 streams (mostly Flash 5) still stop early.
  • Normal-mode action lists as scripts: read past, not turned into ActionScript.

A class not described here ends the stream it is in: MFC objects carry no length, so nothing after it can be found. Phoenix keeps what came before it (the layers before, and the layer it was in up to it), reads the other streams, and says which parts are missing when the document opens.
